# Skipper 概要设计

依据 `docs/需求.md`。本文确定模块怎么拆、数据怎么流、两条主流程停在哪。类的内部实现、FFmpeg 参数和界面尺寸留到详细设计。

## 目标

桌面程序完成四步：列出目录第一层视频，按用户勾选的定位手段取证，可选地收下用户指定的一集及其片头片尾作为标准，算出每集的片头片尾，再按用户确认过的时间流复制出新文件。

界面、应用层、定位、视频操作分开。依赖只有一条：

```
界面 → 应用层 → 定位
         ↓
      视频操作（实现应用层定义的端口）
```

定位是纯计算。它接收已经取好的证据，返回时间区间。它不读盘、不创建进程、不出现窗口类型。

## 模块

| 模块 | 目录 | 职责 |
| --- | --- | --- |
| 定位 | `src/domain` | 搜索窗、标准模板对齐、章节挑选、音频比对、黑帧成段、合并、手改校验、保留区间与关键帧对齐 |
| 应用层 | `src/application` | 分析与导出的编排、会话、进度、取消、单集失败隔离 |
| 视频操作 | `src/infrastructure` | 枚举文件、ffprobe、抽指纹、画面采样、流复制、临时文件 |
| 界面 | `src/ui` | Qt Widgets 窗口与适配层。适配层把 `QString` 与普通类型互转，并把工作线程的回调送回界面线程 |

第一版界面用 Qt Widgets。换界面时只重写 `src/ui`。

构建用 CMake。四个目标分开链接：`domain` 不链接另外三层；`application` 只链接 `domain`；`infrastructure` 不链接界面和定位的实现细节，只实现应用层的端口头文件；可执行文件把四者接上。这样编译期就维持依赖方向。

语言为 C++20。界面之外使用 `std::string`、结构体和枚举。

## 运行形态

同一时间只有一个分析或导出。应用层接口是同步的，在调用方的线程里跑完，并用回调报告进度。适配层在工作线程上调用它，进度和结果通过队列回到 Qt 界面线程。

取消令牌由适配层持有。应用层在每集之间查看；视频操作在等待外部进程时查看，并在取消后结束该进程。

分析会话只留在内存里。关闭程序后丢弃。

## 核心数据

时间单位是秒，用 `double`。路径用 `std::string`，文件身份就是绝对路径。

| 类型 | 内容 |
| --- | --- |
| `Chapter` | 标题、起点、终点 |
| `Fingerprint` | 窗口起点、每个指纹点代表的秒数、`uint32` 点列 |
| `VisualSample` | 时间、黑场比例、饱和度 |
| `Segment` | 起点、终点、来源 |
| `TimeRange` | 起点、终点 |
| `StandardMark` | 标准视频路径、可空的片头区间、可空的片尾区间 |
| `DetectionMethods` | 标准、章节、音频、黑帧是否启用。四项默认都为真 |
| `EpisodePlan` | 路径、文件名、时长、可空的片头、可空的片尾 |
| `ConfirmedEpisode` | 路径、是否排除、可空的片头起止、可空的片尾起止 |
| `Progress` | 序号、总数、文件名、阶段 |
| `ItemResult` | 路径、状态、原因码 |

来源 `SegmentSource`：`Standard`、`Chapter`、`Audio`、`BlackFrame`、`BlackFrameAndAudio`、`Manual`。

状态 `ItemStatus`：`Exported`、`Excluded`、`Skipped`、`Failed`。

原因码由界面翻成中文，下层不拼展示句子：

| 原因码 | 含义 |
| --- | --- |
| `NoVideos` | 目录第一层没有匹配的视频 |
| `StandardInvalid` | 标准视频的时间不成立，分析没有开始取证 |
| `AudioUnavailable` | 整组没有做音频比对 |
| `NoSegments` | 确认后两头都空 |
| `OutputExists` | 目标文件已存在 |
| `CannotRead` | 读或探测失败 |
| `ExportFailed` | 写出失败 |
| `Cancelled` | 用户取消 |

阶段 `Stage`：`Probe`、`Fingerprint`、`BlackFrame`、`Match`、`Export`。

定位使用的常量集中在 `DetectionLimits`：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 最短 / 最长 | 15 / 180 秒 | 只约束自动定位 |
| 片头窗 | 片长的 25% 与 600 秒取较短 | |
| 片尾窗 | 结尾 600 秒 | |
| 合并间隔 | 3 秒 | 片尾黑帧与音频 |
| 整段重合 | 匹配长度达到较短窗口的 90% | 需求里的「几乎整段重合」。90% 是本设计补上的阈值。只用于两两自动比对 |
| 标准覆盖 | 对齐重合达到标准区间的 80% | 需求里的「覆盖标准区间的大部分」。80% 是本设计补上的阈值 |

黑场比例和饱和度的合格线在详细设计里对照样片校准，常量放在定位，不放在 FFmpeg 命令里。

## 端口

应用层定义端口，视频操作实现。

| 端口 | 能力 |
| --- | --- |
| `VideoListing` | 列出目录第一层里扩展名匹配的绝对路径 |
| `MediaProbe` | 时长、内嵌章节、关键帧时间；Chromaprint 是否可用 |
| `AudioFingerprint` | 对给定时间窗生成 `Fingerprint`。窗口由调用方传入 |
| `VisualScan` | 对给定时间窗返回 `VisualSample` 序列 |
| `VideoExport` | 按若干保留区间流复制到临时文件，成功后改成最终文件名；失败或取消时删除临时文件 |
| `OutputFiles` | 创建 `output/`、判断最终文件是否已存在 |

输出文件名由定位里的纯函数决定：`<原主名>_trimmed<原扩展名>`。`OutputFiles` 只负责把它放进所选目录的 `output/`。

扩展名在 `VideoListing` 判断，不区分大小写：`mp4`、`mkv`、`avi`、`mov`、`webm`、`ts`、`m2ts`、`wmv`、`flv`。

## 分析

`analyze(directory, standard, methods, progress, cancel)`。`standard` 可空。`methods` 的四项默认都启用。

1. 列出视频。结果为空则返回 `NoVideos`，不创建 `output/`，也不写会话。
2. 按文件名不区分大小写的字典序排列。
3. `methods.standard` 为假时丢掉 `standard`。为真时，标准视频必须在这份列表里。先探测它的时长。区间不满足手改规则时返回 `StandardInvalid` 和字段错误，不对其余视频取证，不创建 `output/`。两头都空则忽略这份标准。
4. 勾选了音频，或标准的某一头确实要做模板对齐时，才询问 Chromaprint 是否可用。需要音频而不可用时记下 `AudioUnavailable`。标准视频仍保留用户给出的区间。
5. 对每一集：
   - 探测时长和章节。失败则该集记为 `Failed` / `CannotRead`，不进入可编辑列表，下一集继续。标准视频在第 3 步已经探测过。
   - 定位根据时长算出片头窗和片尾窗。某一头的标准区间比该窗更长时，这一头的窗放宽到至少这段区间的长度：片头从 0 起算，片尾贴着文件结尾。
   - 有标准的那一头，且音频可用：抽取标准区间本身的模板指纹，并抽取其余每一集在该搜索窗内的指纹，供模板对齐。这一头不再做两两指纹。
   - 没有标准的那一头：音频已勾选、可用，且至少有两集时，抽取搜索窗指纹，供两两比对。
   - 勾选了黑帧，且该集不是「已有片尾标准的标准集」时，扫描片尾窗的画面样本。
6. 全部证据连同 `methods` 交给定位，得到每集的 `EpisodePlan`。
7. 返回成功探测的计划、失败集、标准错误，以及是否跳过了音频。成功后会话只留下目录和每集时长。计划和失败列表不留在会话里。

取证按集串行，保证进度和取消简单。端口本身不禁止以后在视频操作内部并行，本期不并行。

搜索窗的规则在定位。视频操作只收到已经算好的起点和终点。模板指纹的窗口就是用户给出的标准区间。

## 定位

定位对外两个入口：

- `resolve(证据列表, 可空的标准模板, 启用的手段) → 每集的片头和片尾`
- `planKeepRanges(时长, 片头, 片尾, 关键帧) → 保留区间`

内部按通道分开，合并处单独一个类型，避免章节、音频、黑帧互相调用。

### 章节

片头词：`Intro`、`Introduction`、`OP`、`Opening`、`片头`、`片头曲`。

片尾词：`Credits`、`Credit`、`ED`、`Ending`、`Outro`、`片尾`、`片尾曲`。

词后表示结束的名称（`Intro End`、`片头结束` 一类）不匹配。启用章节时，区间要落在对应搜索窗内，时长在 15–180 秒。片头取最早的一段，片尾取最晚的一段。未勾选章节时这一通道没有候选。

### 音频

点的时间是 `窗口起点 + 下标 × 每个点的秒数`。片尾指纹覆盖文件尾部那段窗口，时间直接加上窗口起点，不把音频倒放。

两两比较采用与 Intro Skipper 相同的做法：为指纹点建立倒排索引，相同点对齐后取最长的连续重合。每一集在所有配对里保留最长的一段有效匹配。两侧的起止可以不同。

一对的重合长度达到较短窗口的 90% 时，丢掉这一对。

未勾选音频、不足两集，或 Chromaprint 不可用时，两两音频通道没有候选。有标准模板且音频可用时，模板对齐仍可只针对其余视频进行；不可用则该对齐没有候选。

### 标准模板

标准视频上，用户给出的区间直接成为该头的结果，来源为 `Standard`。不经过 15–180 秒和搜索窗。

其余视频把模板指纹与自己的搜索窗指纹对齐，做法与两两比对相同：倒排索引、相同点对齐、取最长连续重合。重合长度达到模板时长的 80% 时采用。结果区间的起点是对齐位置，终点是起点加上模板时长，并且整个区间要落在放宽后的搜索窗内。来源为 `Standard`。达不到 80% 时，这一头没有标准候选，改走自动通道。

只提供一头模板时，另一头不进入本通道。

### 黑帧

只在勾选了黑帧时处理片尾窗里的 `VisualSample`。合格样本收成连续段；间隔不超过 3 秒的段可以合成一段。最后只留下时长在 15–180 秒、且整段落在片尾窗内的一段。有多段时取结束时间更靠近文件结尾的一段。

### 合并

未勾选的通道没有候选。四项都未勾选时，两头都空。某一头有标准时，标准视频采用用户区间。其余视频有标准对齐结果就采用，来源为 `Standard`。没有对齐结果时，再走该头的自动顺序。

片头的自动顺序：章节，然后两两音频。

片尾的自动顺序：有章节就用章节。没有章节时，黑帧和两两音频都有效，且重叠或相距不超过 3 秒，则合并。合并后仍须在 15–180 秒内，否则留下较长的那一段。两段都有效但不能合并时，取结束时间更靠近文件结尾的一段。来源记为 `BlackFrame`、`Audio` 或 `BlackFrameAndAudio`。

没有候选的那一头为空。

## 确认与手改

确认页的初值来自当次返回的 `EpisodePlan`。用户改过的时间留在界面表格里。导出时提交的是 `ConfirmedEpisode` 列表，里面是排除标记和四个时间，不是来源。来源显示由界面比较原结果和当前时间后更新。

应用层在导出前调用定位的 `validateEdits`：

- 某一头的起点和终点要么都有，要么都空。
- 有值时起点早于终点，两者都在 `[0, 时长]`，终点可以等于时长。
- 两头都有值时，片头终点不晚于片尾起点。
- 这些检查不使用 15–180 秒，也不使用搜索窗。

任一集不通过时，返回该集和字段错误，不创建 `output/`，不写出文件。界面留在确认页并标出该集。格式和空值由界面先挡一层；起止是否成立以应用层的结果为准。

与自动结果相比，数值有变化的那一头，来源改为 `Manual`。清空的一头保持为空。

两头都空的集不导出，结果为 `Skipped` / `NoSegments`。用户排除的集为 `Excluded`。

## 导出

`export(directory, confirmed, progress, cancel)` 在校验通过后：

1. 创建 `output/`。
2. 对确认列表里的每一集：
   - 已排除：`Excluded`。
   - 两头都空：`Skipped` / `NoSegments`。
   - 最终文件已存在：`Skipped` / `OutputExists`。
   - 否则读取关键帧，交给 `planKeepRanges`，再交给 `VideoExport`。
3. 一集失败记为 `Failed` / `ExportFailed`，删除它的临时文件，继续下一集。
4. 取消时停止后续集，删除当前临时文件，已经改名完成的文件保留。当前集的结果为 `Cancelled`。

保留顺序：

1. 片头起点之前。片头从 0 开始则没有这一段。
2. 片头终点到片尾起点。缺的那一头用 0 或时长补上。
3. 片尾终点之后。片尾一直到结尾则没有这一段。

空段不写入。

关键帧对齐由定位完成，视频操作按对齐后的区间流复制：

- 保留段的起点落到不晚于该时间的关键帧。0 始终可以作为起点。
- 保留段的终点落到不早于该时间的关键帧。时长始终可以作为终点。
- 对齐后起点不早于终点的段丢掉。
- 相邻段重叠时合成一段，重叠只保留一次。

临时文件与最终文件同目录，完成后改名。改名失败视为该集 `ExportFailed`，并删除临时文件。

## 界面

一个主窗口，三种状态。

| 状态 | 界面做的事 |
| --- | --- |
| 选择 | 选目录、展示按名称排好的文件、勾选定位手段、可指定一集为标准并填写片头片尾、开始分析。四个时间框一直显示；没选中标准，或取消「标准」时禁用。没有视频时展示 `NoVideos`。标准时间不成立时留在本页并标出 `StandardInvalid` |
| 确认 | 每集一行：文件名、时长、片头起止、片尾起止、来源、排除。探测失败的集单独列出原因，不能编辑。需要音频却没做成时展示「未能进行音频比对，已改用其余已选手段」。确认或返回选择 |
| 进度与结果 | 展示序号、总数、文件名、阶段。提供取消。结束后按状态列出每一集 |

确认状态在校验失败时保持不变。分析或导出进行中，开始和确认不可再次点击。返回选择时丢掉确认页上的修改；下一次成功分析覆盖会话里的目录和时长。

系统托盘可用时显示托盘图标。关闭主窗口改为隐藏。悬停提示「Skipper — 剪掉片头和片尾」。双击或菜单「显示主界面」恢复窗口，菜单「退出」结束程序。提示在图标显示之后再设置。没有托盘时，关闭窗口即退出。

## 测试

定位用固定证据做单元测试，不启动 FFmpeg：

- 搜索窗在短片和长片上的边界
- 章节的最早片头、最晚片尾、结束词、时长不够
- 音频最长匹配、两侧时间不同、90% 整段重合被丢弃、片尾窗口偏移
- 标准视频保留用户区间；其余视频在覆盖达到 80% 时得到同样时长的对齐区间；不足 80% 时退回自动通道
- 标准区间长于搜索窗时，窗口被放宽
- 片尾合并、超过 180 秒时留下较长的一段、只有黑帧或只有音频
- 手改的半空、越界、重叠，以及超过 180 秒仍然通过
- 关键帧对齐方向、重叠合成、对齐后变空的段
- 关掉章节和音频后，片尾只留下黑帧；只开音频时用音频匹配；四项都关掉时，即使带了标准证据，两头仍为空

视频操作用短样片做少量集成测试：枚举不含子目录、输出文件名、目标已存在则跳过、取消后没有半截文件。
