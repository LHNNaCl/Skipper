## 2. 公共约定

时间是秒，类型 `double`。比较使用 `time.hpp`：

| 常量 | 值 | 用途 |
| --- | --- | --- |
| `kTimeEpsilon` | `0.001` | 手改、重叠、区间是否为空、来源是否算改过 |
| `kWindowSlack` | 一个指纹点的秒数，缺省 `0.128` | 指纹换算后的窗口边界 |

`nearlyEqual(a, b)` 为 `abs(a - b) <= kTimeEpsilon`。`nearlyLess(a, b)` 为 `a < b - kTimeEpsilon`。

路径是绝对路径的 `std::string`。文件身份就是路径。文件名是路径的最后一段。

`limits.hpp` 的 `DetectionLimits`：

| 字段 | 值 |
| --- | --- |
| `minSegmentSec` | 15 |
| `maxSegmentSec` | 180 |
| `introFraction` | 0.25 |
| `introCapSec` | 600 |
| `creditsWindowSec` | 600 |
| `mergeGapSec` | 3 |
| `fullWindowRatio` | 0.90 |
| `templateCoverage` | 0.80 |
| `maxGapPoints` | 1 |
| `maxBucketSize` | 50 |
| `maxHammingBits` | 5 |
| `blackPercent` | 90 |
| `darkPercent` | 70 |
| `maxSaturation` | 20 |
| `visualGapSec` | 1.0 |

`blackPercent`、`darkPercent`、`maxSaturation` 是第一版画面合格线。饱和度按 FFmpeg `signalstats` 的 0–255 刻度。以后只改这一处。

## 4. 取消与进程

`CancelToken` 持有 `std::atomic<bool>`。界面线程把它置为已取消。应用层在每集之间、每个外部命令之前调用 `cancelled()`。

`ProcessRunner`（基础设施）用 `CreateProcess` 启动进程，参数是 `vector<string>`，不经过 shell。标准输出和标准错误分别读完。取消时对进程句柄调用 `TerminateProcess`，等待结束后返回失败，并由调用方当成取消。退出码非 0 也是失败。调用方只把失败变成原因码，不把 stderr 原文交给界面。

同一 `ProcessRunner` 同一时刻只有一个子进程。句柄用互斥量保护，以便界面线程取消、工作线程等待。

## 5. 定位算法

### 5.1 搜索窗

`windowFor(duration, limits)`：

- 片头长度 = `min(duration * introFraction, introCapSec, duration)`，且不小于 0。窗为 `[0, 片头长度)`。
- 片尾长度 = `min(creditsWindowSec, duration)`。窗为 `[duration - 片尾长度, duration)`。

`widen(window, templateDuration, duration, intro)`：模板时长不超过窗长时原样返回。否则片头窗改为 `[0, min(duration, templateDuration))`，片尾窗改为结尾 `min(duration, templateDuration)` 秒。

自动候选 `accepted(range, window)`：时长在 `[minSegmentSec, maxSegmentSec]`，且 `range` 整体落在窗内。边界各放宽 `kWindowSlack`。

### 5.2 输出文件名

`outputFileName(fileName)`：去掉最后一个扩展名得到主名，结果为 `主名 + "_trimmed" + 原扩展名`（含点号，保留原大小写）。`ep01.mkv` 得到 `ep01_trimmed.mkv`。

### 5.3 章节

`pickChapter(chapters, window, kind, limits)`。

词表按长度从长到短：

| 种类 | 词 |
| --- | --- |
| 片头 | `introduction`、`opening`、`intro`、`op`、`片头曲`、`片头` |
| 片尾 | `credits`、`credit`、`ending`、`outro`、`ed`、`片尾曲`、`片尾` |

匹配步骤：

1. 章节没有标题则跳过。
2. ASCII 字母转成小写，其余字符保留。
3. 从左到右找词。ASCII 词的左侧必须是开头或非字母数字，右侧必须是结尾或非字母，因此 `OP1`、`ED2` 算匹配，`HOPE`、`EDITED` 不算。中文词按子串匹配。
4. 词后若只隔空白、`:`、`：`、`-`、`—` 就出现 `end` 或 `结束`，这次出现作废，继续找下一个词。`Intro End`、`片头结束`、`OP: End` 因此不匹配。
5. 任一出现生效，则该章节属于这一类。

区间要被 `accepted` 接受。片头取起点最早的一段，起点相同再取终点更早的。片尾取终点最晚的一段，终点相同再取起点更晚的。没有合格章节则返回空。

ffprobe 没有 `end_time` 时，终点用下一章节的起点；最后一章用文件时长。没有 `title` 的章节不参与。

### 5.4 音频对齐

`matchFingerprints(lhs, rhs, limits)` 返回两侧各自的 `TimeRange`，或空。

1. 任一侧没有点，返回空。
2. 为右侧建立倒排索引：指纹值到下标列表。某一值的出现次数大于 `maxBucketSize` 时，从两侧忽略该值。
3. 用完全相同的指纹点收集候选偏移 `j - i`。若 `maxHammingBits > 0`，再按步长抽样，把汉明距离不超过该值、且命中足够多次的偏移也并入候选。
4. 对每个候选偏移，沿对角线重扫：两侧对应点的汉明距离不超过 `maxHammingBits` 时记为命中。把命中的左侧下标排序，扫描最长的一段。相邻下标的差可以是 1，也可以空出至多 `maxGapPoints` 个点。
5. 这段的时长用左侧的 `秒数 × 点数`（空出的点算进时长）。把起点下标换回两侧时间：`窗口起点 + 下标 × 该侧每个点的秒数`。
6. 取所有偏移里时长最长的一段。时长相同取左侧起点更早的。

两两自动比对再经过 `accepted`，并且匹配时长达到较短那个搜索窗的 `fullWindowRatio` 时，整对作废。

`bestPairwise(fingerprints, windows, limits)`：对所有无序对调用上面的比对。每一集在自己的合格结果里保留时长最长的一段，时长相同保留起点更早的。少于两份指纹时返回全空。

`matchTemplate(templ, target, window, limits)`：调用同一套对齐。覆盖率 = 重合时长 / 模板区间时长。覆盖率小于 `templateCoverage` 则返回空。否则目标区间起点是对齐到的目标时间，终点是起点加模板时长。该区间必须落在 `window` 内（边界放宽 `kWindowSlack`），并且终点不超过文件窗的终点。放不下则返回空。

### 5.5 黑帧成段

`pickBlackFrame(samples, window, duration, limits)`：

1. 样本按时间排序。合格样本满足 `blackPercent >= 90`，或同时满足 `blackPercent >= 70` 与 `saturation <= 20`。
2. 连续合格样本合成一段。相邻合格样本的时间差大于 `visualGapSec` 时切开。
3. 两段的间隔不大于 `mergeGapSec` 时再合成一段。间隔指前一段终点到后一段起点。
4. 合成结果用 `accepted` 过滤。
5. 留下终点最靠近文件结尾的一段，终点相同则留更长的一段。没有则返回空。

样本时间为文件内的绝对秒，不需要再加窗起点。

### 5.6 收成一段

`resolve(episodes, standard, limits, methods)`。`standard` 可空。`methods` 缺省时四项都启用，旧的调用仍然按全部手段计算。有标准且 `methods.standard` 为真时，模板对齐只对路径不同的其他集做。`methods.standard` 为假时，即使传入了标准证据，也不采用用户区间，也不做模板对齐。

`methods.chapter` 为假时不挑章节。`methods.audio` 为假时不做两两音频。`methods.blackFrame` 为假时不收黑帧。被关掉的通道在下面各步都没有结果。

片头：

1. 该集是标准视频且标准含片头：采用用户区间，来源 `Standard`。
2. 否则若模板对齐成功：来源 `Standard`。
3. 否则若章节有结果：来源 `Chapter`。
4. 否则若两两音频有结果：来源 `Audio`。
5. 否则为空。

片尾：

1. 该集是标准视频且标准含片尾：采用用户区间，来源 `Standard`。
2. 否则若模板对齐成功：来源 `Standard`。
3. 否则若章节有结果：来源 `Chapter`。
4. 否则取黑帧候选和两两音频候选：
   - 只有一个：来源对应 `BlackFrame` 或 `Audio`。
   - 两个都有，且重叠或间隔不大于 `mergeGapSec`：并集为 `[较早起点, 较晚终点]`。并集通过 `accepted` 时来源为 `BlackFrameAndAudio`。并集不通过时留下时长更长的一个，时长相同留终点更晚的。
   - 两个都有但不能合并：留终点更晚的一个。
5. 否则为空。

有标准的那一头不做两两音频。没有模板指纹时，第 2 步没有结果，直接进入自动顺序。标准视频自己的用户区间不经过 `accepted`。

### 5.7 手改校验

`validate(episodes, durations, limits 不使用)`。`durations` 是路径到时长。已排除的集跳过。

对每一头：

| 条件 | 结果 |
| --- | --- |
| 起点、终点都空 | 这一头为空 |
| 只填了一个 | `HalfEmpty`，字段为这一头 |
| 起点不早于终点 | `Order`，字段为这一头的起点 |
| 起点小于 0，或终点大于时长 | `OutOfRange`，字段为越界的那一个。终点等于时长合格 |

两头都有值，且片头终点晚于片尾起点：`Pair` / `Overlap`。片头终点等于片尾起点合格。

路径不在 `durations` 里：该集 `CannotRead` 不在这里报，由导出拒绝。校验函数对未知路径追加 `OutOfRange` 到 `Intro`，使导出不会开始。

`sameEndpoint(a, b)`：都空为相同；都有值且起点、终点各自 `nearlyEqual` 为相同。`sourceAfterEdit(original, edited)`：相同则保留原来源，不同则为 `Manual`。确认页的来源显示调用它。

### 5.8 保留区间

`planKeepRanges(duration, intro, credits, keyframes)`。`intro`、`credits` 是可空的 `TimeRange`。

逻辑段：

1. 有片头且片头起点大于 `kTimeEpsilon`：`[0, 片头起点)`。
2. 主体起点是片头终点，没有片头则是 0。主体终点是片尾起点，没有片尾则是时长。起点早于终点时留下 `[主体起点, 主体终点)`。
3. 有片尾且时长减片尾终点大于 `kTimeEpsilon`：`[片尾终点, 时长)`。

关键帧列表始终补上 0 和时长，排序去重。

- 段起点对齐到不大于它的最大关键帧。没有则用 0。
- 段终点对齐到不小于它的最小关键帧。没有则用时长。
- 对齐后起点不早于终点的段丢掉。
- 按起点排序。下一段起点不晚于当前终点时合成一段，终点取较晚者。

返回的每段满足起点早于终点。

## 6. 视频操作

外部程序从 `PATH` 查找 `ffprobe` 与 `ffmpeg`。进程启动时查找一次并记住绝对路径。找不到时，探测、指纹、画面和导出都失败。

### 6.1 列举

`FileListing::list(directory)`：只迭代该目录的直接子项。保留普通文件，扩展名不区分大小写，属于：

`mp4`、`mkv`、`avi`、`mov`、`webm`、`ts`、`m2ts`、`wmv`、`flv`

排序：ASCII 字母转成小写后，按 UTF-8 字节的无符号顺序。返回绝对路径。

### 6.2 探测

时长和章节：

```text
ffprobe -v error -print_format json -show_format -show_chapters -i <file>
```

时长取 `format.duration`。没有则取第一条视频流的 `duration`。都没有则失败。章节取 `start_time`、`end_time`、`tags.title`，按第 5.3 节补终点。

关键帧，对每个切点 `t` 读 `[max(0, t - 10), min(duration, t + 10)]`：

```text
ffprobe -v error -print_format json -select_streams v:0 -skip_frame nokey
  -read_intervals <start>%<end> -show_entries frame=best_effort_timestamp_time
  -show_frames -i <file>
```

解析出的时间落在该闭区间内才保留。一次导出把所有切点的关键帧并在一起。

`chromaprintAvailable()`：执行 `ffmpeg -hide_banner -muxers`，输出含 muxer 名 `chromaprint` 则为真。结果缓存到进程结束。

### 6.3 指纹

优先：

```text
ffmpeg -hide_banner -loglevel error -ss <start> -t <length> -i <file>
  -vn -ac 1 -ar 11025 -f chromaprint -fp_format raw -
```

标准输出按小端 `uint32` 依次读取。`secondsPerPoint = length / points.size()`。没有点则返回空指纹，调用方把这一路当缺失，不让整集失败。

`-ss` 放在 `-i` 前面，输出时间从 0 开始，所以 `windowStartSec` 必须设为调用方传入的 `start`，不能从包里的时间戳读。

muxer 不存在时，先抽出同窗口的 wav，再执行 `fpcalc -raw -plain -length <length>`。`fpcalc` 也不存在则 `chromaprintAvailable()` 为假，应用层不再调用指纹。抽指纹过程失败与「没有点」相同，这一路为空。

### 6.4 画面采样

```text
ffmpeg -hide_banner -loglevel info -ss <start> -t <length> -i <file> -an
  -vf fps=2,blackframe=amount=0:threshold=32,signalstats,metadata=print
  -f null -
```

从 stderr 解析每一帧的 `blackframe` 的 `pblack`、`t`，以及 `signalstats` 的 `SATAVG`。样本时间 = `start + t`。解析不到的帧丢弃。命令失败时返回空样本列表，不让整集失败。

### 6.5 导出

`OutputFiles`：

- `finalPath(directory, fileName)` = `directory/output/` + `outputFileName(fileName)`
- `tempPath(final)` = 在最终文件名的主名后插入 `.part`，保留原扩展名。例如 `ep01_trimmed.mkv` → `ep01_trimmed.part.mkv`。多段裁切的中间文件同理为 `ep01_trimmed.part.0.mkv`。
- `exists` 用文件系统判断最终路径
- `createOutputDir` 创建 `directory/output`

`VideoExport::write(source, temp, ranges, cancel)`：

1. `ranges` 为空则失败。
2. 只有一段：直接切到 `temp`。
3. 多段：每段切到 `temp + "." + 序号`，写 concat 列表，再复制到 `temp`，然后删除各段和列表。
4. 任一步失败或取消：删除 `temp`、各段和列表。

单段命令：

```text
ffmpeg -y -hide_banner -loglevel error
  -ss <start + slack> -itsoffset <slack> -to <end> -i <source>
  -map 0 -c copy -avoid_negative_ts auto
  <temp>
```

`slack` 只在 Matroska/WebM、视频带 B 帧、且起点大于 0 时为 `3/23 + 0.001` 秒，否则为 0（此时不写 `-itsoffset`）。FFmpeg 对这类容器会把输入 `-ss` 再提前 3/23 秒，正好落在上一个关键帧。流复制会留下这一整组画面和字幕，音频却从请求的时间开始，听起来就是只有声音错位。`-itsoffset` 把多出来的提前量补回时间轴，输出的零点仍是原来的起点。`-avoid_negative_ts auto` 按容器需要平移时间戳；`make_zero` 按最早的 DTS 归零，B 帧的显示时间会比音频晚一截。

多段时每段同样切出，再：

```text
ffmpeg -y -hide_banner -loglevel error
  -f concat -safe 0 -i <list> -map 0 -c copy
  <temp>
```

concat 列表每行是 `file '<绝对路径>'`，反斜杠改成斜杠，路径里的单引号写成 `'\''`。

应用层在 `write` 成功后把 `temp` 改名为最终文件。改名时目标已存在，或改名失败：删除 `temp`，该集 `ExportFailed`。

## 7. 应用层

`Session` 在分析成功后保存目录和每集时长，供导出校验和关键帧裁切使用。`plans`、探测失败列表和 `audioUnavailable` 只出现在当次返回值里，确认页自己保存编辑。同一时间由界面保证只有一个调用。

进度回调在工作线程触发。`index` 从 1 起，`count` 是本次要走过的集数。

### 7.1 分析

`analyze(directory, standard, methods, progress, cancel)`：

1. 列举。空则 `reason = NoVideos`，不写会话。
2. 排序后的列表就是处理顺序。
3. `methods.standard` 为假时丢掉 `standard`。否则 `standard` 有值时：
   - 路径不在列表中：`StandardInvalid`，不取证。
   - 两头都空：丢掉标准，按自动分析。
   - 先探测该集。探测失败：`StandardInvalid`，字段错误为空，不取证。
   - `validate` 只含这一集。有字段错误：`StandardInvalid` 并带回错误，不取证。
   - 通过则把 `Endpoint` 收成 `TimeRange`，探测结果留待后面复用。
4. 勾选了音频，或标准的某一头要做模板对齐时，才读取 `chromaprintAvailable()`。需要音频而结果为假时 `audioUnavailable = true`。
5. 若已取消：`reason = Cancelled`，不写会话。
6. 对每一集发 `Probe` 进度。标准集复用第 3 步的探测。其余集探测失败则进入 `failures`，原因 `CannotRead`，不进入证据列表。
7. 对证据列表里的每一集计算搜索窗。某一头有模板时，所有集的这一头都按模板时长放宽。
8. 音频可用，且这一头确实要抽指纹时，发 `Fingerprint` 进度：
   - 有片头模板：抽模板区间一份；其他集各抽片头窗一份。
   - 没有片头模板、勾选了音频、且证据至少两集：每集抽片头窗。
   - 片尾按同样规则处理。
9. 勾选了黑帧时发 `BlackFrame` 进度。没有片尾标准时每集都扫描片尾窗。有片尾标准时，标准集不扫描，其他集扫描，以便对不上时退回自动规则。未勾选黑帧时不扫描。
10. 若已取消：`reason = Cancelled`，不写会话。
11. 发 `Match` 进度，调用 `resolve(..., methods)`。
12. 写入目录和每集时长，并返回 `reason = None`、`plans`、`failures`、`audioUnavailable`。

指纹或画面一步失败时，该路证据为空，集仍留在 `plans` 里。

### 7.2 导出

`export(confirmed, progress, cancel)`：

1. 没有成功分析过：`batchReason = ExportFailed`，不创建目录。
2. 用会话里的时长调用 `validate`。已排除的集不参与。有错误：`validationFailed = true`，不创建目录。
3. 创建 `output/`。失败：`batchReason = ExportFailed`。
4. 按 `confirmed` 的顺序，`count` 为其长度。每一集发 `Export` 进度：
   - 已取消：当前集 `Cancelled`，删除它的临时文件，不再处理后面的集，`cancelled = true`。
   - `excluded`：`Excluded`。
   - 两头都空：`Skipped` / `NoSegments`。
   - 最终文件已存在：`Skipped` / `OutputExists`。
   - 路径不在会话计划里：`Failed` / `CannotRead`。
   - 否则读关键帧。失败则 `Failed` / `ExportFailed`。
   - `planKeepRanges` 的结果为空：`Failed` / `ExportFailed`。
   - `write` 后改名。成功为 `Exported`。取消按上一条处理。其余失败为 `ExportFailed`，并删除临时文件。
5. 返回各项结果。已经改名完成的文件保留。

## 8. 界面

主窗口标题 `Skipper`，最小 960×640。三个页面叠在同一窗口里。文案集中在 `text.hpp`。

控制器把 `Session` 和各基础设施实现放在 `QThread` 上。进度和结果用 `Qt::QueuedConnection` 回到界面线程。取消先把 `CancelToken` 置位，再让 `ProcessRunner` 结束当前子进程。分析或导出进行中，开始分析和开始导出不可再点。

### 8.1 时间框

空字符串是空。否则接受以下形式，前后空白忽略：

| 输入 | 秒 |
| --- | --- |
| `90` | 90 |
| `90.5` | 90.5 |
| `1:30` | 90 |
| `1:30.25` | 90.25 |
| `01:02:03` | 3723 |
| `01:02:03.25` | 3723.25 |

分和秒必须小于 60。其他形式在框上标红，不发起分析或导出。

显示用 `HH:MM:SS`；有小数时用三位毫秒，例如 `00:01:30.250`。

### 8.2 选择页

- 按钮「选择目录」，标签显示绝对路径。
- 表：文件名、单选「标准」。最多一集为标准。
- 四个时间框一直显示：片头起点、片头终点、片尾起点、片尾终点。选中一集且「标准」勾选时才可编辑。
- 时间框下方有「定位手段」：标准、章节、音频、黑帧，默认都勾选。取消「标准」时时间框禁用，已填时间不送去分析。
- 「开始分析」。没有文件时禁用。
- 没有视频时显示「这个目录下没有可处理的视频」。
- 标准不成立时留在本页，标出对应时间框，并显示「标准时间不正确」。标准集探测失败时显示「无法读取标准视频」。

开始分析前，界面只在「标准」勾选且选中了一集时解析时间框。格式不合法则不调用 `analyze`。未勾选「标准」时不解析这些框。

### 8.3 确认页

横幅：`audioUnavailable` 时显示「未能进行音频比对，已改用其余已选手段」。

表列：排除、文件名、时长、片头起点、片头终点、片尾起点、片尾终点、来源。探测失败的集另列在表下，显示文件名和「无法读取」，没有时间框。

来源在字段每次变化时调用 `sourceAfterEdit` 更新。显示词：

| 来源 | 词 |
| --- | --- |
| `Standard` | 标准 |
| `Chapter` | 章节 |
| `Audio` | 音频 |
| `BlackFrame` | 黑帧 |
| `BlackFrameAndAudio` | 黑帧+音频 |
| `Manual` | 手动 |
| 空 | 未检出 |

按钮「返回」回到选择页，丢弃本次计划在界面上的编辑，会话仍保留到下一次分析覆盖。「开始导出」先做时间格式检查，再调用 `export`。校验失败时留在本页，标出错误单元格。

### 8.4 进度与结果

进度行：`阶段 序号/总数 文件名`。阶段词：探测、指纹、画面、定位、导出。进度条为 `index / count`。按钮「取消」。

结束后表列：文件名、状态、说明。

| 状态 | 说明 |
| --- | --- |
| 已导出 | 空 |
| 已排除 | 已排除 |
| 已跳过 / `NoSegments` | 没有可剪的片头或片尾 |
| 已跳过 / `OutputExists` | 输出文件已存在 |
| 失败 / `CannotRead` | 无法读取 |
| 失败 / `ExportFailed` | 导出失败 |
| 失败 / `Cancelled` | 已取消 |

有取消时，表下显示「已取消，其余未处理」。按钮「完成」回到选择页。

批量 `batchReason == ExportFailed` 且没有任何单集结果时，显示「无法创建输出目录」。

### 8.5 托盘

系统托盘可用时创建 `QSystemTrayIcon`，图标与窗口相同。图标显示之后再设置提示「Skipper — 剪掉片头和片尾」。右键菜单为「显示主界面」和「退出」。双击图标恢复窗口。

关闭窗口时，若托盘存在且不是从「退出」来的，则忽略关闭并隐藏窗口。托盘不可用时接受关闭并退出。退出前先让控制器结束正在进行的工作。

## 9. 测试

领域测试不启动 FFmpeg。下面每行是一条用例，输入直接写成秒或指纹点。

搜索窗：

- 时长 2400：片头 `[0, 600)`，片尾 `[1800, 2400)`。
- 时长 1200：片头 `[0, 300)`，片尾 `[600, 1200)`。
- 时长 60：片头 `[0, 15)`，片尾 `[0, 60)`。
- 片头模板 200、原片头窗 75、时长 300：放宽为 `[0, 200)`。
- 片尾模板 700、原片尾窗 600、时长 2000：放宽为 `[1300, 2000)`。

章节：

- `OP1` 位于 `[10, 100)`，窗 `[0, 600)`：采用。
- `Intro End`、`片头结束`、`OP: End`：不采用。
- `HOPE`、`EDITED`：不采用。
- 两段片头都合格：取起点更早的。两段片尾都合格：取终点更晚的。
- 时长 10 秒或 200 秒：不采用。

音频，每个点 1 秒，便于心算：

- 左侧点 `[1,2,3,9]`，右侧点 `[8,1,2,3]`：对齐到左侧 `[0,3)`、右侧 `[1,4)`。
- 重合达到较短窗的 90%：该对作废。
- 两对都合格：每集留下更长的一对。
- 模板 10 个点，目标只连续命中 7 个：覆盖 70%，拒绝。命中 8 个：接受，目标区间长度等于模板时长。
- 接受后的区间超出搜索窗：拒绝。

黑帧与合并：

- 黑场比例 95 的样本连成 20 秒：采用，来源黑帧。
- 黑场比例 75、饱和度 10，与上一条同样处理。饱和度 40 且黑场比例 75：不合格。
- 两段间隔 3 秒：合成。间隔 3.1 秒：保持两段，再取终点更晚且时长合格的一段。
- 片尾同时有黑帧和音频，间隔 2 秒，并集时长 100 秒：来源黑帧+音频。并集 200 秒：留下较长的那一段。
- 有片尾章节：不再看黑帧和音频。
- 标准片头存在：该集用用户区间；另一集覆盖足够时用来源标准，覆盖不足时用它自己的章节。
- 关掉章节和音频：片尾采用黑帧。只开音频：片尾采用音频匹配。四项都关掉，即使传入标准证据：两头都空。

手改与关键帧：

- 只填片头起点：`HalfEmpty`。起点大于终点：`Order`。终点大于时长：`OutOfRange`。片头终点晚于片尾起点：`Overlap`。
- 片头 200 秒：校验通过。
- 已排除的集时间不合法：不产生错误。
- 关键帧 `0,10,20,30`，保留段 `[12, 28)`：对齐成 `[10, 30)`。
- 对齐后首尾相接的两段：合成一段。对齐后起点不早于终点：丢掉。

基础设施集成测试用两段不超过 5 秒的样片，单独启用：

- 子目录里的视频不会出现在列表中。
- 输出名带 `_trimmed`，扩展名不变。
- 最终文件已存在时跳过，文件内容不变。
- 导出过程中取消后，不存在 `.part` 文件，已改名完成的文件还在。
