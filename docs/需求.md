# Skipper 需求

选定一个目录后，把该目录第一层的视频当作同一组素材，为其中每一集另存一个去掉片头和片尾的新文件。原片保持不变。

片头和片尾靠这一组视频互相参照来定位：反复出现的音频、文件里的章节名，以及片尾常见的黑场或纯色底。用户也可以指定其中一集，并给出它的片头、片尾时间，把这段声音当作标准。每一集使用自己的起止时间。

## 范围

本期只处理片头和片尾。

界面、定位、视频操作分开实现。界面负责选择、确认和展示；定位根据证据算出每集的起止时间；视频操作负责读盘、取证和按时间点写出新文件。

## 用户流程

1. 选择一个目录。
2. 列出该目录第一层里扩展名匹配的视频，按文件名排序。子目录不进入。没有匹配文件时说明原因并停在这一步。
3. 可以指定其中一集作为标准，并填写它的片头区间、片尾区间，或两者都填。不指定时，完全按自动规则定位。
4. 分析这一组视频，列出每一集的片头、片尾时间，以及该时间来自标准、章节、音频还是黑帧。
5. 用户核对每一集的时间。可以修改片头、片尾的起止，可以清空某一头，也可以补上程序没找到的时间；可以排除某一集。确认后再导出，导出使用确认页上的时间。
6. 导出过程展示进度，并可以取消。
7. 结束后列出每一集的结果：已导出、已排除、已跳过或失败，并带上原因。

只有 1 个视频时仍然可以分析。此时没有其他视频可做音频比对，只使用章节和黑帧；若该集被指定为标准，则采用用户给出的时间。音频比对至少需要 2 个视频；不足 2 个且没有可用的标准音频时，跳过音频比对，并在结果里说明。

## 输入

只读取所选目录第一层、扩展名不区分大小写的文件：

`mp4`、`mkv`、`avi`、`mov`、`webm`、`ts`、`m2ts`、`wmv`、`flv`

其余文件不进入列表。

## 输出

新文件写到所选目录下的 `output/`。文件名为原名加 `_trimmed`，扩展名不变。例如 `ep01.mkv` 写成 `output/ep01_trimmed.mkv`。

`output/` 在用户确认导出时创建。分析本身不创建该目录。

目标文件已存在时跳过该集并说明，不覆盖。取消时保留已经完成的新文件；正在写的那一集先写临时文件，取消或失败时不留下半截结果。

## 定位

每一集最多得到一段片头和一段片尾。时间以秒计，可以有小数。一段有效区间必须同时满足：

- 整个区间落在对应的搜索窗内
- 时长不短于 15 秒，不长于 180 秒

| 段落 | 搜索窗 |
| --- | --- |
| 片头 | 片长的前 25% 与前 10 分钟里较短的那一段 |
| 片尾 | 最后 10 分钟 |

片头之前的内容保留。片尾之后的内容保留。

### 证据

三条通道各自独立取证，再按下面的规则收成一段。

**章节。** 读取文件内嵌章节。名称匹配片头模式时作为片头候选，匹配片尾模式时作为片尾候选。默认模式为：

- 片头：`Intro`、`Introduction`、`OP`、`Opening`、`片头`、`片头曲`
- 片尾：`Credits`、`Credit`、`ED`、`Ending`、`Outro`、`片尾`、`片尾曲`

名称在这些词之后明确表示结束（如 `Intro End`、`片头结束`）时不算匹配。时长不在 15–180 秒内的章节不采用。片头搜索窗内有多段匹配时，采用最早的一段。片尾搜索窗内有多段匹配时，采用最晚的一段。

**音频。** 使用 Chromaprint。片头只比对各集的片头搜索窗，片尾只比对各集的片尾搜索窗。两两比较，每一集保留落在时长门限内的最长匹配。比较方式与 Intro Skipper 相同：相同指纹点对齐后，取最长的连续重合区间。片尾音频从文件尾部取出，匹配到的时间要换算回该集自己的时间轴。

两集在搜索窗里几乎整段重合时，丢掉这对比较结果，避免把正片或重复文件当成片头片尾。音频比对不可用时，章节和黑帧继续进行，并说明音频比对没有执行。

**黑帧。** 只用于片尾。在片尾搜索窗内，把持续的黑场，以及近乎纯色、低饱和背景上的字幕，收成一段。这段也必须落在 15–180 秒内。

**标准。** 分析前可以指定已列出的一集，并给出片头区间、片尾区间，或两者。标准视频上，给出的那一头直接采用，来源为标准。这些时间只须满足确认页的手改规则，不受 15–180 秒和搜索窗限制。

指定了标准视频但某一头只填了一个时间，或时间不成立时，停在选择页并标出，不对其余视频取证。两头都空则视为没有指定标准。

对其余视频，用标准区间里的音频做模板，在对应搜索窗里找对齐位置。重合覆盖标准区间的大部分时，采用对齐到的那段，时长与标准区间相同，来源为标准。标准区间比搜索窗更长时，搜索窗放宽到至少能放下这段区间。对不上的视频，这一头改走自动规则。

只给出片头时，片尾仍走自动规则。只给出片尾时，片头仍走自动规则。音频比对不可用时，标准视频仍使用给出的时间；其余视频无法按这段声音对齐，并说明音频比对没有执行，然后改走章节和黑帧。

### 收成一段的规则

某一头有标准时：标准视频采用用户给出的区间。其余视频优先采用标准音频对齐的结果。没有对齐结果时，再按该头的自动顺序。

片头的自动顺序：

1. 有效的片头章节
2. 有效的音频两两匹配

片尾的自动顺序：

1. 有有效的片尾章节时，采用该章节的起止时间
2. 没有片尾章节时，在黑帧和音频两两匹配里采用有效结果。两段都有效，且互相重叠或间隔不超过 3 秒时，合并成一段。合并后的时长仍须在 15–180 秒内；超出时采用较长的那一段。两段都有效但合并不了时，采用结束时间更靠近文件结尾的那一段

某一头没有任何有效结果时，这一头留空，表示不剪。两头都空时，该集默认不导出；用户在确认页补上时间后可以导出。

15–180 秒和搜索窗只约束自动定位。标准时间和确认页上的手改时间不受这两条限制。

## 确认页上的时间

每一集显示片头起点、片头终点、片尾起点、片尾终点。程序检测到的值作为初始值，来源标明标准、章节、音频、黑帧，或黑帧与音频的合并。用户在确认页改过的那一段，来源改为手动。

手改规则：

- 某一头的起点和终点要么都有，要么都空。都空表示这一头不剪。
- 有值时，起点早于终点，并且两个时间都在 0 到该集时长之间（终点可以等于时长）。
- 片头和片尾都有值时，片头终点不晚于片尾起点。
- 时间格式不合法时，界面标出该集，并停在确认页，不开始导出。
- 起止是否成立由应用层判定。界面只检查格式和空值。

两头都空、且用户没有补时间的集，不导出。

## 导出

按确认页上的时间，用流复制拼接保留下来的部分，不重新编码。一集的保留顺序是：

1. 片头开始之前
2. 片头结束到片尾开始
3. 片尾结束之后

某一头没有被删掉时，对应的切口不存在，相邻部分连成一段。空的部分不写入。

流复制只能在关键帧处切开。每个切口选择少切掉正片的一侧：

- 一段保留内容的起点，对齐到不晚于确认时间的关键帧
- 一段保留内容的终点，对齐到不早于确认时间的关键帧

因此边界上可能留下不足一个关键帧间隔的片头或片尾。对齐后若相邻片段重叠，重叠部分只保留一次。

## 单集结果

| 结果 | 条件 |
| --- | --- |
| 已导出 | 确认后至少有一头有时间，用户没有排除该集，且新文件写完 |
| 已排除 | 用户在确认时去掉了该集 |
| 已跳过 | 确认后片头和片尾都为空，或目标文件已存在 |
| 失败 | 读文件、取证或写出失败 |

某一集失败或跳过时，其余集继续。

## 模块边界

依赖方向只有一条：界面 → 应用层 → 定位。视频操作实现应用层使用的端口，供取证和导出调用。定位不调用界面，也不启动外部程序。

| 模块 | 负责 | 交给别人 |
| --- | --- | --- |
| 界面 | 选目录、指定标准视频及其时间、列表、检测结果、修改或清空时间、排除某一集、确认、进度、取消、结果 | 指纹计算、章节和黑帧规则、FFmpeg 参数、读写文件 |
| 应用层 | 按「枚举 → 取证 → 定位 → 确认 → 导出」编排；转发进度和取消；隔离单集失败 | 窗口和文案；片头片尾的判定公式 |
| 定位 | 根据时长、章节、指纹点和黑帧证据，算出每集可空的片头区间和片尾区间，并标明来源 | 界面控件；进程、文件和解码 |
| 视频操作 | 枚举一层视频；探测时长、章节和关键帧；抽出音频并生成指纹；检测黑帧；按给定时间点流复制出新文件 | 什么样的区间算片头或片尾 |

界面提交给应用层的请求只有两种：分析一个目录，并可带上可选的标准视频及其片头片尾区间；按已确认的计划导出。界面收到的是待处理列表、每集的检测计划、进度，以及每集的结果。进度至少包含当前集序号、总集数、文件名和阶段。界面用这些数据组织中文文案。

定位的输入是普通数据：文件标识、时长、章节列表、片头和片尾的指纹点、片尾黑帧区间，以及可选的标准模板指纹。输出是每集的片头区间、片尾区间和来源。来源为标准、章节、音频、黑帧，或黑帧与音频的合并。

实现为 C++ 桌面程序。界面框架只出现在界面及其适配层。

## 外部程序

探测、抽音频、黑帧检测、流复制和拼接使用 FFmpeg / ffprobe。音频指纹使用 Chromaprint（FFmpeg 的 chromaprint 支持或 `fpcalc`）。两者需要能在本机被调用。
